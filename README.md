# sp500-sim

Симулятор торговли на исторических данных S&P 500. Он прокручивает дневные цены день за днём, спрашивает у стратегии, что делать, исполняет приказы с комиссией и проскальзыванием и считает результат. Каждый прогон сохраняется в базу, поэтому прогоны можно сравнивать между собой. К каждому прогону есть HTML-отчёт с графиками и таблицей сделок.

Прогоны можно запускать из командной строки и с сайта (форма в браузере и JSON API). Бумаги можно собирать в портфель с весами. Дневные свечи, рыночные приказы.

## Установка

Нужен Python 3.11 или новее.

```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
pip install -e . --no-deps
```

Файл `requirements.lock` фиксирует точные версии всех библиотек, так что результаты не меняются из-за обновления `pandas` или `yfinance`. В нём уже есть всё: и сайт, и инструменты разработки (тесты, линтер).

Без lock-файла: `pip install -e .` для командной строки, `pip install -e ".[web]"` с сайтом, `pip install -e ".[dev,web]"` для разработки.

## Быстрый старт

```
sp500-sim run
```

Команда читает `config.toml`, при первом запуске скачивает цены, прогоняет стратегии, печатает таблицу итогов, сохраняет прогон в `results/results.db` и пишет отчёт `results/run_<номер>.html`. Откройте отчёт в браузере.

## Настройки: config.toml

Все настройки лежат в файле. Свой вариант можно держать в `config.local.toml` (он не попадает в git) и запускать так: `sp500-sim run config.local.toml`.

| Раздел | Параметр | Что значит |
|---|---|---|
| `[data]` | `ticker` | `SPY` (фонд, дивиденды учтены) или `^GSPC` (сам индекс) |
| | `start`, `end` | период; без `end` берётся всё до последнего дня |
| | `cache_dir` | куда сохранять скачанные цены |
| `[broker]` | `commission` | комиссия с сделки, `0.0005` = 0,05% |
| | `slippage` | цена хуже на эту долю: покупка дороже, продажа дешевле |
| | `min_change` | не торговать, если доля акций меняется меньше чем на эту величину |
| `[run]` | `cash` | стартовые деньги |
| `[output]` | `dir` | папка для базы и отчётов |
| `[[strategies]]` | `type`, `name`, `color`, `portfolio`, `rebalance`, остальное | стратегия и её параметры; блоков может быть сколько угодно. `color = "#e0709f"` задаёт цвет линии на графиках и плитки в отчёте (необязательно, иначе берётся цвет из палитры). `portfolio` и `rebalance` описаны в разделе «Портфель с весами для стратегии» |

Опечатки в названиях параметров и неверные значения программа не пропускает: она сразу пишет, что и где не так.

## Команды

```
sp500-sim run [config.toml]      # прогон; --refresh скачать цены заново,
                                 # --no-save не сохранять, --no-report без отчёта
sp500-sim runs                   # список сохранённых прогонов со статусами
sp500-sim compare 1 2 3          # сравнить прогоны и показать, чем они отличаются
sp500-sim report 2 -o report.html  # пересоздать отчёт сохранённого прогона
sp500-sim serve                  # запустить сайт (http://127.0.0.1:8000)
sp500-sim -v run                 # подробный лог (каждая сделка)
```

Если запускали с другой папкой результатов (`[output] dir`), добавьте `--dir папка` к командам `runs`, `compare` и `report`.

## Сайт

```
sp500-sim serve                       # http://127.0.0.1:8000
sp500-sim serve --port 9000           # другой порт
sp500-sim serve --config my.toml      # значения формы из другого файла настроек
```

Сайт работает с той же базой `results/results.db`, что и командная строка: прогоны из консоли видны на сайте и наоборот.

Страницы:

| Адрес | Что там |
|---|---|
| `/` | форма нового прогона: тикер, период, брокер, стратегии (до 6) с параметрами вида `n=200` и выбором цвета для каждой. Значения по умолчанию берутся из `config.toml`. Ошибки показываются под нужным полем |
| `/runs` | список прогонов со статусами «идёт», «готов», «ошибка» |
| `/runs/<номер>` | страница прогона: пока он идёт, обновляется сама, потом показывает отчёт. Кнопка «Повторить с этими настройками» заполняет форму из этого прогона |
| `/compare` | выбор прогонов и сравнение: метрики рядом и чем отличались настройки, код и данные |

Оформление в стиле «матовое стекло»: градиентный фон, полупрозрачные карточки, цветные плитки стратегий. Есть светлая тема и её ночная версия. По умолчанию берётся системная, кнопка в правом верхнем углу переключает её, выбор запоминается. Те же стили и графики в отчётах `results/run_<номер>.html`: отчёт открывается без интернета, графики в нём нарисованы для обеих тем.

Прогон выполняется в фоне: сайт сразу создаёт запись со статусом «идёт», а расчёт идёт отдельным потоком. Прогоны выполняются по очереди, по одному. Если сервер остановили во время прогона, при следующем запуске такой прогон получит статус «ошибка: прерван».

### JSON API

Документация и пробные запросы: `http://127.0.0.1:8000/api/docs`.

| Запрос | Что делает |
|---|---|
| `POST /api/runs` | запускает прогон; тело - настройки в JSON, как в `config.toml`, но без `output` и `data.cache_dir`; ответ `202` с номером прогона. `?refresh=true` скачивает цены заново |
| `GET /api/runs` | список прогонов |
| `GET /api/runs/<номер>` | статус, ошибка, описание и метрики |
| `GET /api/runs/<номер>/equity` | кривая капитала по каждой стратегии |
| `GET /api/compare?ids=1,2` | метрики и отличия нескольких прогонов |

Пример:

```
curl -X POST localhost:8000/api/runs -H 'content-type: application/json' -d '{
  "data": {"ticker": "SPY", "start": "2010-01-01"},
  "strategies": [{"type": "buy_and_hold"}, {"type": "sma_trend", "n": 100}]
}'
curl localhost:8000/api/runs/1
```

### Безопасность

- По умолчанию сайт слушает только этот компьютер (`127.0.0.1`). Входа и паролей в нём нет, поэтому не открывайте его в сеть (`--host 0.0.0.0`) без прокси с авторизацией.
- Пути (папка кэша и папка результатов) задаёт только сервер, через сайт их выбрать нельзя.
- Свой код стратегий сайт не принимает: можно выбирать только стратегии из `REGISTRY`.
- Для публичного сервиса нужны ещё свой источник цен (Yahoo не разрешает такое использование), ограничения на число прогонов и авторизация.

## Портфель с весами для стратегии

Стратегия может торговать не одной бумагой, а набором ваших тикеров с весами:

```toml
[[strategies]]
name = "Мой портфель"
type = "buy_and_hold"
portfolio = { AAPL = 40, MSFT = 30, KO = 30 }   # веса в процентах, в сумме 100
rebalance = "yearly"                            # never, monthly, quarterly, yearly

[[strategies]]
name = "Просто SPY"                             # без portfolio: бумага из [data]
type = "buy_and_hold"
```

На графике капитала портфель идёт отдельной линией, рядом с другими стратегиями. Так его удобно сравнивать с индексом. На сайте то же самое делается в блоке стратегии: поле «Портфель» (`AAPL 40, MSFT 30, KO 30`, а без весов `AAPL, MSFT, KO` бумаги берутся поровну) и список «Ребаланс».

Как это считается:

- Одна стратегия берёт свой портфель, а стратегии без `portfolio` торгуют бумагой из `[data]`. Портфелей и бумаг можно задать несколько, но не больше 10 бумаг в одном портфеле и 40 разных во всём прогоне.
- Все стратегии считаются на общем периоде: только дни, когда торговались все бумаги прогона. Если одна из бумаг появилась позже, период начинается с её первого дня. В отчёте об этом пишется.
- В первый день деньги делятся по весам и бумаги покупаются по цене открытия следующего дня. Комиссия и проскальзывание берутся с каждой сделки по каждой бумаге.
- `rebalance = "never"`: веса дальше меняются вместе с ценами (купил и держу). Остальные значения в первый торговый день нового месяца, квартала или года продают лишнее и докупают недостающее, чтобы вернуть веса. Каждая такая сделка тоже платит комиссию.
- Стратегии с сигналом (например, `sma_trend`) смотрят на индекс портфеля с постоянными весами. Когда сигнал «выйти», продаются все бумаги сразу, когда «войти», покупаются все.
- В таблице сделок у портфеля есть колонка «Тикер».

## Мой портфель: ваши акции

Если у вас есть реальные акции, внесите их вручную: тикер, сколько штук и «Стоимость позиции». Это **средняя цена, по которой вы купили одну акцию**, так она показана в вашем приложении.

```toml
[my_portfolio]
name = "Мой портфель"      # необязательно
color = "#7d6fe0"          # необязательно
positions = [
  { ticker = "AAPL", qty = 10, avg_price = 190 },
  { ticker = "MSFT", qty = 5,  avg_price = 420 },
]
```

На сайте то же самое в карточке «Мой портфель»: три поля в строке, кнопка «+ Добавить акцию», пустые строки игнорируются.

В результате появляется отдельная плитка, линия на графиках и таблица «Мои позиции». Стратегии можно не задавать совсем, тогда будет только ваш портфель. А можно оставить, например, «Просто SPY», и сравнить.

Что вы увидите:

- **Плитка.** Главная цифра: прибыль или убыток к вложенному, то есть стоимость сейчас относительно того, сколько вы заплатили. Рядом: стоимость, вложено, прибыль в деньгах, просадка.
- **Таблица «Мои позиции».** По каждой бумаге: штук, ваша средняя цена, вложено, цена сейчас, стоимость, прибыль в деньгах и в процентах, доля в портфеле. Внизу итог.
- **График.** Сплошная линия: как менялась бы стоимость ваших нынешних акций (штук × цена за день). Пунктир: сколько вы вложили. Разрыв между ними справа это ваша прибыль или убыток.

Как это считается:

- Количество акций считается неизменным, сделок и комиссий нет. График показывает историю цен ваших нынешних акций. Это не ваша фактическая доходность: покупать вы могли позже, а прибыль считается от вашей средней цены.
- «Цена сейчас» это последняя цена в данных (дата указана в заголовке столбца), а не цена на этот момент.
- Курсы валют не учитываются: цены берутся в валюте биржи, а средняя цена должна быть в той же валюте. Если ввести рубли или злотые при долларовой бумаге, прибыль будет неверной.
- Если ваша средняя цена отличается от цены в данных больше чем в 6 раз, отчёт покажет предупреждение. Чаще всего это значит, что вместо цены одной акции введена стоимость всей позиции.
- Все линии считаются на общем периоде, как и раньше.

## Как сравнивать прогоны

Меняете что-то в `config.toml` (комиссию, период, параметр стратегии), запускаете `sp500-sim run`, потом:

```
sp500-sim compare 1 2
```

Внизу команда покажет, что именно отличалось: настройки, коммит кода и отпечаток данных. Если результаты разные, а отличий нет, значит, что-то в прогоне не воспроизводится, и это стоит выяснить.

В базе (`results/results.db`, SQLite, режим WAL) для каждого прогона хранятся: статус, время, коммит git (с `+dirty`, если были незакоммиченные правки), тикер и период, отпечаток цен и время их скачивания, полные настройки, метрики стратегий, кривая капитала и все сделки. Базу можно открыть любым SQLite-клиентом и считать свои запросы. База от прошлой версии программы обновляется при первом открытии сама, данные сохраняются.

## Как работает

1. Решение принимается по цене закрытия дня i.
2. Исполняется по цене открытия дня i+1, с комиссией и проскальзыванием.
3. Стратегия получает только историю до дня i включительно, будущего у неё нет.

Цены берутся с поправкой на сплиты и дивиденды. Кэш цен называется по тикеру и периоду, например `data/SPY_2000-01-01_latest.csv`. Для периода без `end` кэш сам не обновляется, для свежих данных запускайте с `--refresh`.

## Своя стратегия

Стратегия - класс с методом `target(hist)`. Он получает таблицу цен до сегодняшнего закрытия и возвращает желаемую долю акций в портфеле от 0.0 (всё в деньгах) до 1.0 (всё в акциях). Значение вне этого диапазона останавливает прогон с понятной ошибкой.

1. Создайте файл `src/sp500_sim/strategies/my_strategy.py`:

```python
import pandas as pd


class MyStrategy:
    def __init__(self, n: int = 50):
        self.n = n

    def target(self, hist: pd.DataFrame) -> float:
        if len(hist) < self.n:
            return 0.0
        close = hist["Close"]
        return 1.0 if close.iloc[-1] > close.iloc[-self.n :].mean() else 0.0
```

2. Добавьте её в `REGISTRY` в `src/sp500_sim/strategies/__init__.py`:

```python
from .my_strategy import MyStrategy

REGISTRY = {..., "my_strategy": MyStrategy}
```

3. Укажите в `config.toml`:

```toml
[[strategies]]
name = "Моя"
type = "my_strategy"
n = 50
```

## Разработка

```
pytest                    # тесты
ruff check .              # линтер
ruff format .             # форматирование
pre-commit install        # проверки перед каждым коммитом
```

Тесты не ходят в интернет: цены для них искусственные. Сайт проверяется через встроенный тестовый клиент, в том числе миграция старой базы, статусы фоновых прогонов и защита от чужих путей. Они проверяют сам симулятор на заранее известных ответах: «купить и держать» без комиссий даёт ровно рост цены, пустая стратегия не трогает деньги, приказ исполняется на следующий день по открытию, стратегия не видит будущего, один и тот же прогон даёт один и тот же результат.

CI в GitHub Actions на каждый коммит запускает линтер, проверку форматирования и тесты на Python 3.11 и 3.12 с версиями из `requirements.lock`; в том числе проверяет сайт. Раз в неделю отдельная задача проверяет, не ломается ли проект на самых новых версиях библиотек.

### Обновление версий библиотек

```
pip install uv
uv pip compile pyproject.toml --extra dev --extra web --python-version 3.11 -o requirements.lock
pip install -r requirements.lock
pytest
```

Если тесты прошли, коммитьте новый `requirements.lock`.

## Что пока не умеет

Лимитные заявки, короткие продажи и маржа, минутные данные, разделение истории на период подбора и проверки. Данные Yahoo среднего качества, в них нет компаний, вышедших из индекса или обанкротившихся, поэтому на отдельных акциях результаты будут завышены.
