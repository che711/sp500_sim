# sp500-sim

Симулятор торговли на исторических данных S&P 500. Он прокручивает дневные цены день за днём, спрашивает у стратегии, что делать, исполняет приказы с комиссией и проскальзыванием и считает результат. Каждый прогон сохраняется в базу, поэтому прогоны можно сравнивать между собой. К каждому прогону есть HTML-отчёт с графиками и таблицей сделок.

Сейчас одна бумага, дневные свечи, рыночные приказы.

## Установка

Нужен Python 3.11 или новее.

```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
pip install -e . --no-deps
```

Файл `requirements.lock` фиксирует точные версии всех библиотек, так что результаты не меняются из-за обновления `pandas` или `yfinance`. Для разработки (тесты, линтер) в нём уже всё есть.

## Быстрый старт

```
sp500-sim run
```

Команда читает `config.toml`, при первом запуске скачивает цены, прогоняет стратегии, печатает таблицу итогов, сохраняет прогон в `results/results.db` и пишет отчёт `results/run_<номер>.html`. Откройте отчёт в браузере.

## Настройки: config.toml

Все настройки лежат в файле. Свой вариант можно держать в `config.local.toml` (он не попадает в git) и запускать так: `sp500-sim run config.local.toml`.

| Раздел | Параметр | Что значит |
|---|---|---|
| `[data]` | `ticker` | `SPY` (фонд, дивиденды учтены) или `^GSPC` (сам индекс) |
| | `start`, `end` | период; без `end` берётся всё до последнего дня |
| | `cache_dir` | куда сохранять скачанные цены |
| `[broker]` | `commission` | комиссия с сделки, `0.0005` = 0,05% |
| | `slippage` | цена хуже на эту долю: покупка дороже, продажа дешевле |
| | `min_change` | не торговать, если доля акций меняется меньше чем на эту величину |
| `[run]` | `cash` | стартовые деньги |
| `[output]` | `dir` | папка для базы и отчётов |
| `[[strategies]]` | `type`, `name`, остальное | стратегия и её параметры; блоков может быть сколько угодно |

Опечатки в названиях параметров и неверные значения программа не пропускает: она сразу пишет, что и где не так.

## Команды

```
sp500-sim run [config.toml]      # прогон; --refresh скачать цены заново,
                                 # --no-save не сохранять, --no-report без отчёта
sp500-sim runs                   # список сохранённых прогонов
sp500-sim compare 1 2 3          # сравнить прогоны и показать, чем они отличаются
sp500-sim report 2 -o report.html  # пересоздать отчёт сохранённого прогона
sp500-sim -v run                 # подробный лог (каждая сделка)
```

Если запускали с другой папкой результатов (`[output] dir`), добавьте `--dir папка` к командам `runs`, `compare` и `report`.

## Как сравнивать прогоны

Меняете что-то в `config.toml` (комиссию, период, параметр стратегии), запускаете `sp500-sim run`, потом:

```
sp500-sim compare 1 2
```

Внизу команда покажет, что именно отличалось: настройки, коммит кода и отпечаток данных. Если результаты разные, а отличий нет, значит, что-то в прогоне не воспроизводится, и это стоит выяснить.

В базе (`results/results.db`, SQLite) для каждого прогона хранятся: время, коммит git (с `+dirty`, если были незакоммиченные правки), тикер и период, отпечаток цен и время их скачивания, полные настройки, метрики стратегий, кривая капитала и все сделки. Базу можно открыть любым SQLite-клиентом и считать свои запросы.

## Как работает

1. Решение принимается по цене закрытия дня i.
2. Исполняется по цене открытия дня i+1, с комиссией и проскальзыванием.
3. Стратегия получает только историю до дня i включительно, будущего у неё нет.

Цены берутся с поправкой на сплиты и дивиденды. Кэш цен называется по тикеру и периоду, например `data/SPY_2000-01-01_latest.csv`. Для периода без `end` кэш сам не обновляется, для свежих данных запускайте с `--refresh`.

## Своя стратегия

Стратегия - класс с методом `target(hist)`. Он получает таблицу цен до сегодняшнего закрытия и возвращает желаемую долю акций в портфеле от 0.0 (всё в деньгах) до 1.0 (всё в акциях). Значение вне этого диапазона останавливает прогон с понятной ошибкой.

1. Создайте файл `src/sp500_sim/strategies/my_strategy.py`:

```python
import pandas as pd


class MyStrategy:
    def __init__(self, n: int = 50):
        self.n = n

    def target(self, hist: pd.DataFrame) -> float:
        if len(hist) < self.n:
            return 0.0
        close = hist["Close"]
        return 1.0 if close.iloc[-1] > close.iloc[-self.n :].mean() else 0.0
```

2. Добавьте её в `REGISTRY` в `src/sp500_sim/strategies/__init__.py`:

```python
from .my_strategy import MyStrategy

REGISTRY = {..., "my_strategy": MyStrategy}
```

3. Укажите в `config.toml`:

```toml
[[strategies]]
name = "Моя"
type = "my_strategy"
n = 50
```

```
src/sp500_sim/
    cli.py          команды run, runs, compare, report

    report.py       HTML-отчёт
    runner.py       один прогон целиком
    strategies/     стратегии и их общий интерфейс
tests/              тесты (pytest)

data/               кэш цен (в .gitignore)
results/            база и отчёты (в .gitignore)
```

## Разработка

```
pytest                    # тесты
ruff check .              # линтер
ruff format .             # форматирование
pre-commit install        # проверки перед каждым коммитом
```

Тесты не ходят в интернет: цены для них искусственные. Они проверяют сам симулятор на заранее известных ответах: «купить и держать» без комиссий даёт ровно рост цены, пустая стратегия не трогает деньги, приказ исполняется на следующий день по открытию, стратегия не видит будущего, один и тот же прогон даёт один и тот же результат.

CI в GitHub Actions на каждый коммит запускает линтер, проверку форматирования и тесты на Python 3.11 и 3.12 с версиями из `requirements.lock`. Раз в неделю отдельная задача проверяет, не ломается ли проект на самых новых версиях библиотек.

### Обновление версий библиотек

```
pip install uv
uv pip compile pyproject.toml --extra dev --python-version 3.11 -o requirements.lock
pip install -r requirements.lock
pytest
```

Если тесты прошли, коммитьте новый `requirements.lock`.

## Что пока не умеет

Несколько бумаг, лимитные заявки, короткие продажи и маржа, минутные данные, разделение истории на период подбора и проверки. Данные Yahoo среднего качества, в них нет компаний, вышедших из индекса или обанкротившихся, поэтому на отдельных акциях результаты будут завышены.
